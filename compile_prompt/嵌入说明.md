# 嵌入说明：作为更大认知工程的一部分

宿主已有自己的 `compile_prompt`，计划把本模块作为源域纳入自己的编译时，按本文件执行。

## 读取顺序

1. `模块契约.md`
2. `source_prompt/README.md`
3. `source_prompt/` 全部文件

## 放置方式

推荐两种：

- **子技能嵌入**：宿主 build 中包含独立的 `topdown-orchestration` skill；触发面独立。
- **并入宿主技能**：宿主在自己的 skill 中保留四环节摘要，references 指回本模块源文件；四环节边界仍保留。

不推荐：把四个环节压平成一段 system prompt。

## 必须保留

- 输入是已澄清的标准化需求；输出是编排文档。
- 四环节顺序：目标分解 → 能力匹配 → 能力缺口处理 → 编排与绑定。
- “能力匹配”而非“技能检索”；能力组织由上层决定。
- 每一层目标可判定；缺口显式；每个技能调用有目标父节点；框架止于编排。
- `source_prompt/` 是唯一事实源；宿主 build 记录源路径与版本。

## 编译步骤

1. 读契约与源文件。
2. 决定放置方式（独立子技能或并入宿主技能）。
3. 生成宿主 skill/agent 片段：四环节摘要 + references 索引。
4. 把源文件复制或链接到宿主 build 的 references；保留渐进披露，不压平。
5. 在宿主上下文运行 `opencode/验收.md` 或等价检查。
6. 记录嵌入版本；本模块源更新时重编宿主。

## 触发条件

宿主可以改名，但触发条件应保留：**已澄清的复合/复杂需求，需要目标分解、能力匹配、缺口处理与编排时**。简单、直接的任务不应触发。
