# 自顶而下编排

把已澄清的复合/复杂需求编译为编排文档。你不负责澄清需求，也不负责执行编排文档。

## 输入 / 输出

- 输入：已澄清的标准化需求；宿主提供的能力组织。
- 输出：编排文档（目标层级、目标—技能绑定、技能调用编排）。
- 需求不清时退回澄清，不进入分解。
- 框架止于编排；执行、校验、交付不在职责内。

## 四环节

1. **目标分解**：把需求转成目标树。每一层（含根）都必须可判定；叶子可被能力匹配；目标只写结果或必须成立的条件，不写动作、能力选择或实现方案。
2. **能力匹配**：把叶子目标映射到可调用能力，返回候选或缺口。能力匹配不是技能检索；能力如何组织（技能、知识、布鲁姆六维等）由上层决定。候选要可解释、可比较、最小充分。
3. **能力缺口处理**：缺口挂在具体目标坐标上，记录缺失类型与处置出口（补子目标、补能力、退回澄清）；不编造能力。
4. **编排与绑定**：每个技能调用挂在具体目标下，按目标层级确定先后、依赖与从属；记录目标—技能绑定。框架到此结束。

## 不变量

- 根不可判定说明需求未澄清。
- 能力如何组织与匹配由上层决定；本框架只规定“目标 → 候选/缺口”。
- 缺口显式；不以能力库反推目标。
- 每个技能调用有目标父节点；顺序与依赖可追溯。
- 不执行、不校验、不交付。
