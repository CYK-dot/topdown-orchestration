# 能力缺口处理

**职责**：把“没有可用能力”转成可定位、可决策的对象。

**输入**：能力缺口（目标坐标、缺失描述）。

**输出**：缺口记录与处置结果。

## 缺失类型

只取四类；“文档缺失”“数据缺失”等是证据形态，不是独立类型：

- **知识**：缺事实、规范、字段定义、领域资料。
- **方法**：缺可执行步骤、算法、流程或验证方法。
- **工具**：缺可调用工具、平台能力或自动化手段。
- **约束**：缺权限、资源、环境、时间窗口或验收限制。

多个类型同时成立时，记录一个主类型，其余作为证据或次类型；主类型选择规则由场景维护者定义，但必须显式。

## 判据

- **显式定位**：缺口挂在具体目标坐标上，缺失类型取上述四类之一，并记录主类型。
- **可分类**：记录类别：目标不清 / 能力缺失 / 平台或权限限制；不同类别走不同出口。
- **可回流**：缺口能回到目标分解或能力匹配，形成下一轮。
- **不越界**：不替用户补需求，不静默生成“看起来能用”的能力；假设必须标记。
- **可积累**：缺口记录能进入能力维护，成为后续迭代输入。
- **可控**：避免缺口爆炸或无限分解；有停止条件或优先级。

## 输出字段

- 目标坐标
- 类别：目标不清 / 能力缺失 / 平台或权限限制
- 缺失类型：知识 / 方法 / 工具 / 约束（可带次类型）
- 证据或现象
- 处置出口：补子目标 / 补能力 / 退回澄清
- 停止条件或优先级：避免缺口无限扩散
