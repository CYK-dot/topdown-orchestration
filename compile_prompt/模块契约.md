# 模块契约

| 字段 | 内容 |
|---|---|
| 模块名 | `topdown-orchestration` |
| 版本 | `0.1` |
| 源入口 | `source_prompt/README.md` |
| 编译入口 | `compile_prompt/README.md` |
| 提供 | 目标分解、能力匹配、能力缺口处理、编排与绑定 |
| 输入 | 已澄清的标准化需求；上层提供的能力组织 |
| 输出 | 编排文档（目标层级、目标—调用绑定、调用编排） |
| 依赖 | 无强制依赖；宿主需提供能力组织 |
| 目标形态 | standalone skill；或宿主认知工程的 embedded 源域 |

## 不变量

- 每一层目标（含根）可判定；根不可判定说明需求未澄清。
- 能力匹配不是技能检索；能力如何组织由上层决定。
- 候选可完整覆盖、部分覆盖（必须带残余缺口）或缺口；缺口显式；不以能力库反推目标。
- 一个能力可产生多个调用实例；每个调用实例只有一个目标父节点，允许 1:N，禁止孤儿。
- 依赖标注端点与类型（层级/前置/产物/门禁）及依据；跨目标互斥、资源竞争、共享产物记入调用间约束。
- 缺口记录类别（目标不清/能力缺失/平台或权限限制）与知识/方法/工具/约束类型。
- 框架止于编排文档，不负责澄清、执行、校验与交付。

## 嵌入约束

- 宿主可以改名、改触发、决定放置位置。
- 宿主必须保留四环节边界、输入/输出边界与上述不变量。
- 宿主不得把四环节压平成一段系统提示词；应保留参考文件与渐进披露。
- `source_prompt/` 是唯一事实源；宿主记录源路径与版本，不复制后漂移。
