# 编排与绑定

**职责**：把目标层级与能力匹配结果合成编排文档；每个调用实例挂在具体目标下，按目标层级确定先后、依赖与从属。

**输入**：目标层级，能力匹配结果。

**输出**：编排文档，至少包含：

- 目标层级：目标 ID、父 ID、完成条件、是否叶子；
- 调用实例：调用 ID、目标 ID、能力或技能、输入、输出、选择理由；
- 依赖：from / to、端点类型（目标 / 调用）、类型（层级 / 前置 / 产物 / 门禁）、依据；
- 调用间约束：from / to、类型（互斥 / 资源竞争 / 共享产物）、依据。

## 依赖类型

- **层级**：父目标要求子目标或其调用成立；端点至少一端为目标。
- **前置**：调用 B 的能力前置条件要求调用 A 的结果或状态。
- **产物**：B 的输入是 A 的输出。
- **门禁**：B 需要某个判定/批准结果（如测试通过、签名验证）。

端点必须显式标注“目标”或“调用”，不得混用。

## 判据

- **调用实例单父**：一个能力可以产生多个调用实例；每个实例只有一个目标父节点；1:N 允许，孤儿禁止。
- **顺序有据**：先后与依赖来自目标层级、能力前置条件与产物依赖，并标注依赖类型与端点。
- **冲突显式**：跨目标的互斥、资源竞争、共享产物记入调用间约束，不只写在候选说明里。
- **最小充分**：只编排目标所需调用，不把候选全部塞进计划。
- **可审计**：记录调用 ID、目标—调用绑定、理由、依赖与输入输出。
- **可执行但不过界**：文档足以交给执行侧，但不规定实现细节；框架不执行、不校验。
- **可变更**：目标或能力变化时，绑定能局部更新。

## 边界

框架止于编排文档。场景机制层可以增加编排策略与门禁规则，但“目标挂载、顺序有据、绑定留痕”是框架不变量。
