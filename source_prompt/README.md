# 自顶而下编排框架 · 知识源

> 何时读我：当已澄清的复合/复杂需求需要被分解为目标树、匹配能力、处理缺口并产出编排文档时。

本目录是平台无关的知识源，人和 LLM 均可读。`compile_prompt/` 负责把它编译为两种形态：

- **standalone skill**：任意 agent 可触发的独立组件；
- **embedded module**：更大认知工程的源域，参与宿主编译。

## 阅读顺序

1. `背景与目标.md`：解决什么问题、边界。
2. `术语与概念.md`：目标树、能力匹配、缺口、编排文档。
3. `框架/README.md`：四个环节。
4. `框架/01`–`04`：逐环节判据与示例。
5. `边界与嵌入.md`：standalone 与 embedded 两种形态。
6. `质量与验收.md`：自检清单。

## 不变量

- 输入必须是已澄清的标准化需求；澄清不是本框架的职责。
- 输出必须是编排文档；执行、校验、交付不是本框架的职责。
- 能力如何组织（技能、知识、布鲁姆六维等）由上层决定；框架只规定目标→候选/缺口的契约。
- 每一层目标都可判定；根不可判定说明需求未澄清。
- 缺口显式；部分覆盖必须留下残余缺口；不以能力库反推目标。
- 一个能力可产生多个调用实例；每个调用实例只有一个目标父节点。
