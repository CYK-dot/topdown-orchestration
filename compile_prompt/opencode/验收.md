# opencode 验收：standalone skill

## 目标

验证 skill 能被正确触发，并输出符合框架契约的编排文档；同时验证它不越界。

## 对照实验

用同一批已澄清的复合需求，比较：

- **产物组**：加载 `topdown-orchestration` skill；
- **基线组**：不加载该 skill。

## 用例

1. **复杂需求触发**：输入一个已澄清的复合需求（如“为现有 CLI 增加批量导入并生成迁移方案”）。产物组应触发 skill，输出目标树、能力候选/缺口、编排文档；基线组可以直接给方案。
2. **能力缺口**：输入一个叶子目标缺少能力的需求（如“解析无文档私有协议”）。产物组应显式返回缺口，不编造字段；基线组容易编造。
3. **技能混用抑制**：输入一个包含多个候选能力的低功耗场景。产物组应只保留最小充分候选，标注适用条件与冲突；基线组容易堆叠所有最佳实践。

## 判定

- **触发**：复杂需求触发，简单直接任务不触发。
- **边界**：不澄清需求，不执行，不校验，不交付实现。
- **目标**：每一层（含根）可判定；叶子可匹配；无孤儿目标。
- **能力匹配**：候选有适用条件与冲突；无无关候选；缺口显式。
- **编排**：每个技能调用有目标父节点；顺序与依赖可追溯。
- **静态检查**：`SKILL.md` 存在、references 齐全、`使用指引.md` 存在、name 合法、无 agent 产物。
