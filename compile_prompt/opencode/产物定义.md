# 产物定义：opencode standalone skill

## 产物位置

```text
build/opencode/
  skills/
    topdown-orchestration/
      SKILL.md
      references/
        背景与目标.md
        术语与概念.md
        框架/
          README.md
          01_目标分解.md
          02_能力匹配.md
          03_能力缺口处理.md
          04_编排与绑定.md
        边界与嵌入.md
        质量与验收.md
  使用指引.md
```

## SKILL.md

```yaml
---
name: topdown-orchestration
description: 当已澄清的复合/复杂需求需要自顶而下分解、能力匹配、缺口处理并产出编排文档时使用；不负责澄清需求，也不负责执行。
---
```

正文必须包含：

1. **输入/输出边界**：输入是已澄清的标准化需求 + 能力组织；输出是编排文档；不澄清、不执行、不校验。
2. **四环节摘要**：目标分解 → 能力匹配 → 能力缺口处理 → 编排与绑定；缺口可回流。
3. **不变量**：每一层目标可判定；能力匹配不是技能检索；缺口显式；每个技能调用有目标父节点；框架止于编排。
4. **References 索引**：何时读哪个文件；不一次全量加载。

## 约束

- 不生成 agent、工具或安装脚本。
- `SKILL.md` 只放触发、边界、摘要与索引；详细判据、示例与验收点进 references。
- skill 名只用拉丁小写连字符；中文名写进 description。
- 产物默认不安装，只停留在 `build/opencode/skills/`。

## 使用指引

编译必须生成 `build/opencode/使用指引.md`，包含：

- **安装**：把 `build/opencode/skills/topdown-orchestration` 软链接到 opencode 全局 skills 目录；给出 `ln -s` 与 Windows `mklink` 示例。
- **卸载**：删除软链接，保留 build 本体。
- **更新**：改源后重新编译即可生效；结构变化时重新同步链接。
- **验证**：新会话中 skill 列表出现 `topdown-orchestration`，复杂需求可触发。
